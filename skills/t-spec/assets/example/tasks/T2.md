# T2 — Wire `--json` into the `list` command

## Context

The `list` command accepts `--json` and prints the serializer output instead
of the table. Without the flag, nothing changes.

## Constraints and contracts

- `todo list --json` prints a JSON array to stdout, one object per todo.
- Output to stdout only; errors to stderr with exit code 1.
- Exit code 0 on success, including the empty list.
- Existing table output stays byte-identical when `--json` is absent.

## Dependencies

- T1 — produces `formatTodosJson(todos: Todo[]): string` in
  `src/format/json.ts`.

## Files

- Modify: `src/commands/list.ts:8-30`
- Modify: `src/commands/list.test.ts`

## Interfaces

- Consumes: `formatTodosJson(todos: Todo[]): string` from `src/format/json.ts`
- Produces: CLI flag `--json` on `todo list`

## Steps

1. In `src/commands/list.ts`, add `.option("--json", "print JSON")` to the
   command definition.
2. In the action handler, before the table rendering:
   ```ts
   if (opts.json) {
     process.stdout.write(formatTodosJson(todos) + "\n");
     return;
   }
   ```
3. In `src/commands/list.test.ts`, add the `--json` test below next to the
   existing table snapshot test.

## Tests

- `list --json prints a JSON array` — run the command against a store with
  two todos, `JSON.parse` stdout, expect length 2 and keys
  `id, title, done`; run: `npx vitest run src/commands/list.test.ts`
- existing `list prints table` snapshot — still passes unchanged.

## Acceptance

- Both tests pass; `todo list` without the flag is byte-identical to before.

## Verification

- `npx vitest run src/commands/list.test.ts` → all passed.
- `npm run build` → no errors.
